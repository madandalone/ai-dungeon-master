# Rules Service (версия 1: наивный поиск)

Пакет `rules_service/` даёт Dungeon Master текст правил, относящихся к действию игрока.
Версия 1 намеренно проста: без эмбеддингов и векторной БД.

## Интерфейс

```python
from rules_service import RulesService

service = RulesService.from_file("srd.md")      # .md, .txt или .pdf (для PDF нужен pypdf)
service.get_rules("jump over a chasm", top_k=3, max_chars=4000)  # -> str
service.search("jump over a chasm")                              # -> list[RuleChunk]
```

- Вход: путь к книге правил и текстовый запрос (обычно текст действия игрока).
- Выход: `get_rules` - строка с заголовками и текстом лучших фрагментов (пустая, если ничего не найдено);
  `search` - список `RuleChunk(title, text)`.
- Подходит под `integration.RulesProvider` (метод `get_rules(query) -> str`).
- Не знает про движок, DM и Backend; зависимостей кроме stdlib нет (`pypdf` только для PDF).

## Как устроено

1. **Загрузка** (`load_text`): `.pdf` читается через `pypdf`, остальное как UTF-8.
2. **Разбиение** (`split_into_chunks`): по markdown-заголовкам `#`..`######`; секция длиннее
   `MAX_CHUNK_CHARS` (1500) режется по абзацам. Для PDF без заголовков весь текст станет секциями
   без названия - качество поиска ниже, лучше подавать markdown-версию SRD.
3. **Индекс**: для каждого фрагмента считается частота слов (заголовок учитывается дважды), по корпусу - IDF.
4. **Поиск** (`search`): сумма `tf/длина * idf` по словам запроса; токены короче 3 символов отбрасываются.
5. **Сборка контекста** (`get_rules`): берутся top-k фрагментов, пока суммарно не превышено `max_chars`
   (фрагмент, не влезший в лимит, не включается целиком, обрезки нет).

## Ограничения (мотивация для RAG)

- Только точное совпадение слов: без лемматизации и синонимов. "leap" не найдёт "jump".
- Язык запроса должен совпадать с языком книги. Русское действие игрока не найдёт правил в
  английском SRD (это проявилось в тестах интеграции). Варианты: перевести запрос, использовать
  мультиязычные эмбеддинги, попросить DM сформулировать поисковый запрос на английском.
- Индекс строится в памяти при старте; нет сохранения на диск и обновления.
- Качество не измерено: нет эталонного набора вопрос -> правильный фрагмент.

## План развития

PDF -> парсинг -> chunks -> embeddings -> векторное хранилище -> semantic search. Интерфейс
`get_rules(query) -> str` при этом должен остаться прежним, чтобы `integration/` и AI DM не менялись.
