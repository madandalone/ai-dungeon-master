# Демо-кампания «Сундук в сторожке»

Цель: показать **один настоящий бросок d20, который выполняет Game Engine**, и повествование ведущего по его результату. В контексте нет монстров, заговоров, прошлых комнат и перемещений, поэтому даже небольшая локальная модель получает простую задачу. Данные лежат в [demo_campaign.json](demo_campaign.json); тот же сценарий проверяется автоматически (`integration/tests/test_demo_campaign.py`).

## Что в кампании

| Поле | Значение |
|---|---|
| Герой | Арагорн, Сила 14, Ловкость 12, Телосложение 13, Интеллект 10, Мудрость 12, Харизма 10, 10 HP, длинный меч |
| Локация | Сторожка: одна комната, стол и старый сундук с заклинившей крышкой, дверь открыта |
| Скрытый сюжет | В сундуке лежит медный ключ. Других секретов нет |
| Безопасное действие | `Осматриваю сундук.` |
| Рискованное действие | `Пытаюсь силой открыть заклинившую крышку сундука.` |

Сюжет передаётся готовым (`authored`), модель кампанию не пишет.

## Запуск сценария

Backend запущен (`./run.sh` или `uvicorn backend.main:app --port 8000`), `.env` настроен. Команды для `curl` (в Windows PowerShell используйте `curl.exe` и одинарные кавычки вокруг JSON). Подставьте `SESSION` и `HERO` из ответов.

1. **Новая сессия** (не переносите историю прежних проверок):

   ```bash
   curl -s -X POST http://127.0.0.1:8000/sessions -H "Content-Type: application/json" -d '{"name": "Сундук в сторожке"}'
   ```

2. **Герой** (`expected_revision` равен 0 для новой сессии; `id` героя в ответе):

   ```bash
   curl -s -X POST http://127.0.0.1:8000/sessions/SESSION/characters -H "Content-Type: application/json" -d '{"expected_revision": 0, "name": "Арагорн", "concept": "Следопыт", "max_hp": 10, "stats": {"strength": 14, "dexterity": 12, "constitution": 13, "intelligence": 10, "wisdom": 12, "charisma": 10}, "starting_item": "Длинный меч"}'
   ```

3. **Кампания** (готовый сюжет, без обращения к модели):

   ```bash
   curl -s -X POST http://127.0.0.1:8000/sessions/SESSION/campaign -H "Content-Type: application/json" -d '{"authored": {"title": "Сундук в сторожке", "hidden_plot": "В сундуке лежит обычный медный ключ. Других секретов нет, врагов и ловушек нет.", "starting_location": "Сторожка", "room_context": "Одна комната: деревянный стол и старый сундук. Крышка сундука заклинила, открыть её голыми руками трудно. Дверь открыта.", "intro_narrative": "Арагорн стоит в небольшой пустой сторожке. Перед ним старый деревянный сундук с заклинившей крышкой. Дверь за спиной открыта."}}'
   ```

4. **Безопасное действие**: ожидается ответ без броска (`status: resolved`).

   ```bash
   curl -s -X POST http://127.0.0.1:8000/sessions/SESSION/turns -H "Content-Type: application/json" -d '{"action_id": "demo-1", "character_id": "HERO", "text": "Осматриваю сундук."}'
   ```

5. **Рискованное действие**: ожидается `202` и `status: awaiting_roll` с проверкой Силы (`ability`, `difficulty`, `modifier` +2, `chance`).

   ```bash
   curl -s -X POST http://127.0.0.1:8000/sessions/SESSION/turns -H "Content-Type: application/json" -d '{"action_id": "demo-2", "character_id": "HERO", "text": "Пытаюсь силой открыть заклинившую крышку сундука."}'
   ```

6. **Бросок d20** выполняет Engine; в ответе событие проверки (бросок, модификатор, сложность, итог) и повествование по исходу:

   ```bash
   curl -s -X POST http://127.0.0.1:8000/sessions/SESSION/turns/demo-2/roll -H "Content-Type: application/json" -d '{"sequence": 1}'
   ```

Те же шаги можно пройти в браузере, кроме шага 3: интерфейс не умеет передавать готовую кампанию, её нужно отправить запросом. Если не отправлять её, при первом ходе ведущий напишет сюжет сам (для маленькой модели это лишний, более тяжёлый запрос).

## Что должно получиться

- Безопасное действие не вызывает бросок. Рискованное вызывает ровно одну проверку Силы, и до броска исход не объявляется.
- При Силе 14 модификатор равен +2: `итог = d20 + 2`, успех при итоге не ниже сложности.
- Успех: крышка открывается, виден ключ; ключ попадает в инвентарь только отдельным действием «Беру ключ». Неудача: крышка закрыта, HP не списываются.
- Повествование относится к сторожке и сундуку, `state_updates` адресованы Арагорну, ревизия растёт на один ход один раз, история не дублируется.

## Как понять, что пошло не так

При ответе `502` модель вернула непригодный ход после одного исправления; сессия при этом не изменилась, действие можно отправить снова с тем же `action_id`. В логе Backend предупреждения вида `invalid AI response operation=plan.decision ... attempt=1 repair=next error=...` показывают, какой шаг и по какой причине отклонён (первая ошибка и результат исправления записываются отдельно). Для разбора полных промптов и сырых ответов включите `AI_DM_LOG_RAW=1` локально: в этих логах есть скрытый сюжет и текст игрока, в общие логи их направлять нельзя.

Даже простая кампания не гарантирует, что конкретная локальная модель (например `qwen2.5:7b`) вернёт валидный JSON. Перед показом прогоните сценарий несколько раз; повторяющаяся ошибка означает дефект интеграции, а не проблему сюжета.
